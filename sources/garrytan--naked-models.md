# "Naked Models Are Stupider" (`garrytan`, essay)

> Garry Tan's point-by-point rebuttal to Kyle Kingsbury's (Jepsen) essay *"The Future of Everything is Lies, I Guess."* Tan concedes every one of Kingsbury's observed LLM failures — the bathroom render, the hallucinated stock graph, the jagged frontier, the "bullshit machine" — and then argues each is a *harness-engineering problem, not a verdict on AI*. The recurring image: Kingsbury is "testing the engine on a bench and concluding that cars are unsafe." Our primary source for the "test the system, not the model" thesis, the "naked model vs. harnessed system" framing, and the cleanest essay-side statement of why the [[patterns/structural/thin-harness-fat-skills]] architecture exists. Essay #4 of Garry's 8-part AI Explainer series.

## Anchor map

Every claim citing this source uses a `#anchor` from this list. The essay is one prose file; anchors are thematic pointers into the author's own section headers (which are unusually clean and make stable anchors). Do not invent anchors outside this list.

- `#root` — the essay as a whole
- `#thesis` — the core move: "naked models are unreliable; the *system* doesn't have to be." Kingsbury's observations are correct, his conclusion is not. "The model is unreliable. The system doesn't have to be."
- `#kingsbury-essay` — the rebuttal target: Kyle Kingsbury / Jepsen; his "32-page essay" *"The Future of Everything is Lies, I Guess"* published "Last week"; a decade of Jepsen "applied skepticism" against CockroachDB/MongoDB/Redis consistency claims
- `#scope-note` — the explicit narrowing: this answers only the **architecture question** ("does model unreliability make useful systems impossible, or an engineering problem?"), not Kingsbury's labor/information-ecology/cultural concerns
- `#engine-on-a-bench` — the governing metaphor: Kingsbury "is testing the engine on a bench and concluding that cars are unsafe"; each cited failure is a *human + raw model + natural language*, with "No skill file… No deterministic tool… No resolver… No harness"
- `#terms-defined` — the in-essay glossary of the series' vocabulary: **skill file** = reusable markdown procedure (not a prompt); **resolver** = routing table for which doc to read; **deterministic code** = same-output-every-time software the model never touches; **harness** = thin conductor running the model in a loop. "Together: thin harness, fat skills." Grounds [[patterns/structural/thin-harness-fat-skills]] and [[patterns/behavioral/latent-vs-deterministic-split]].
- `#claude-code-leak` — "512,000 lines of engineering that Anthropic built around their own model… live repo context, prompt caching, purpose-built tools, session memory, and parallel sub-agents. That's 512,000 lines of evidence that model reliability is an engineering problem, not a philosophical one." Note the *honesty caveat*: "512,000 lines is not simple… Robust implementation is real engineering. Harnesses fail. Skills encode wrong procedures."
- `#stock-data-fix` — the clearest illustration: a model "claimed to download stock prices" and graphed random numbers because "it has no tools… no HTTP client… no API keys." The fix is **a deterministic tool**: "The model never touches the data retrieval. It decides what to look up. The code decides how. Same input, same output, every time." Grounds [[patterns/behavioral/latent-vs-deterministic-split]].
- `#bathroom-decompose` — the 4-step decomposition of Kingsbury's failed Gemini 3D-render task into latent steps (model judgment) + deterministic steps (Pillow/OpenCV/Blender + a geometry-comparison check). "The model does the judgment. The code does the execution. The resolver routes between them. The harness orchestrates the sequence." Concedes the decomposition itself is a *debuggable* failure surface. Grounds [[patterns/behavioral/skill-as-method-call]] (a skill = a parameterized, decomposed procedure) and [[patterns/behavioral/latent-vs-deterministic-split]].
- `#jagged-frontier` — Kingsbury's "jagged technology frontier" (irregular capability boundaries — calculus yes, letter-counting no) reframed: "What it actually means is that you need routing… The jagged frontier is an argument for harness engineering, not against AI… put deterministic code where the model is weak and model judgment where the code can't reason. The resolver maps the territory." Grounds [[patterns/composition/resolver-routing-table]].
- `#brain-resolver-evidence` — the essay's single hardest data point: "I designed my **OpenClaw's brain resolver** to be **80 lines of markdown, in a numbered decision tree** that routes every piece of knowledge to the right directory. When we didn't have it, skills made their own filing decisions and **10 out of 13 were wrong**. When we added it, **misfilings dropped to zero**." (author self-claim; grounds [[patterns/composition/resolver-routing-table]] — real artifact is gbrain `RESOLVER.md` + `_brain-filing-rules.md`, see Why we cite / Contradictions.)
- `#constraints-not-chaos` — Kingsbury's "LLMs are chaotic / input-perturbation-sensitive / adversarially manipulable" conceded for *raw* models, then countered: a skill file is "a 200-line document that says: here's the task, here's the process, here's what good output looks like, here are the tools you have, here are the ones you don't, here's what to do if you're uncertain." "Structured input through a skill file is dramatically less chaotic than freeform natural language… the way banks channel a river." Grounds [[patterns/structural/thin-harness-fat-skills]] (the ~200-line fat-skill shape).
- `#reasoning-red-herring` — chain-of-thought is "the scratchpad, not the product"; cites Anthropic's finding that CoT traces "don't reliably reflect its actual reasoning process," then dismisses it as irrelevant to system output. "He evaluates the scratchpad instead of the answer."
- `#aspirin` — "we don't know why aspirin works either": practical utility doesn't require theoretical completeness (aspirin's mechanism unknown until ~1971; general anesthesia; bicycle stability explained only in 2011). "Engineering can proceed while research continues."
- `#jepsen-wrong-layer` — the central judo move: Kingsbury's Jepsen methodology "is exactly the right approach for AI systems… just applied to the wrong layer." Test the *system*, not the model — "like running Jepsen against the bare filesystem instead of the database." Enumerates a **testing pyramid for agent systems**: unit tests (deterministic code), integration tests (pipeline correctness), **resolver trigger evals** (routing accuracy), **LLM-as-judge evals** (output quality), end-to-end tests (full pipeline). Also names four testable system invariants ("Does the harness prevent hallucinated data from reaching the user? Does the skill file route to deterministic code where precision matters? Does the resolver fire for the right inputs? **Does the entity propagation complete?**"). Grounds [[patterns/quality-bar/skill-pack-bundle]] and [[patterns/composition/resolver-routing-table]].
- `#verified-vs-plausible` — the epistemology answer to Frankfurt-style "bullshit machines": "A naked model produces plausible text. A harnessed system produces verified text." The skill says "check your work against the source data"; deterministic code "compare this output to the ground truth and reject if it diverges." "The system produces a verified result." Grounds [[patterns/quality-bar/complexity-ratchet]] (verification as a load-bearing layer) and [[patterns/behavioral/diarization]] (distilled, checked output).
- `#open-harness` — the open-source argument: "the quality of the verification depends on the quality of the skill file… written by a human." "A closed-source agent can never let you write the skill that verifies its output, because legalism and safetyism prevent the kind of deep customization that real verification requires… The solution is open harnesses where the user controls the verification layer. Not trust. Engineering." Explicitly ties to **Pete Koomen's "AI Horseless Carriages"**: "The user must write their prompt, otherwise we'll be slaves to a system prompt that we can't see."
- `#cars` — the close: car safety came from "engineering the chassis" (seatbelts, crumple zones, ABS, airbags, emissions standards), never from "skepticism about engines." The 8-line imperative ("Build the system. Write the skills. Test the code. Route with resolvers. Make the deterministic parts deterministic. Make the latent (model) parts constrained. Test the system, not the model. And when the system fails — because it will — debug the step that broke, fix the skill, and run it again."). Ends: "The model is the engine. The harness is the car. Build the car."
- `#sign-off` — the closing pitch: "I open-sourced the architecture described in this series. **GBrain is the knowledge layer** to let you build your own personal **OpenClaw/Hermes Agent** that does work for you. **GStack is the skill layer** to go fast with Claude Code." (Links the essay to [[artifacts/plugins/gbrain]] and [[artifacts/plugins/gstack]].)

## Why we cite this

- **The single best essay-side statement of "test the system, not the model."** The [[patterns/quality-bar/skill-pack-bundle]] pattern (a skill ships as a *tested* bundle) and [[patterns/quality-bar/complexity-ratchet]] are usually argued from the gstack `#test` harness; this essay supplies the *rationale* — and its enumerated pyramid (unit / integration / resolver-trigger-eval / LLM-as-judge / e2e) maps one-to-one onto real gstack files (`skill-validation.test.ts`, `skill-e2e-*.test.ts`, `resolver-ask-user-format.test.ts` + `writing-style-resolver.test.ts`, `skill-llm-eval.test.ts`, `skill-routing-e2e.test.ts`). ([[sources/garrytan--naked-models#jepsen-wrong-layer]] ↔ [[sources/garrytan--gstack#test]].)
- **The "naked model vs. harnessed system" framing** — the cleanest articulation in the series of *why* you push intelligence up into skills and execution down into deterministic code ([[patterns/structural/thin-harness-fat-skills]], [[patterns/behavioral/latent-vs-deterministic-split]]). The stock-data and bathroom examples are reusable teaching cases for the latent/deterministic split.
- **A hard, falsifiable resolver result** ([[sources/garrytan--naked-models#brain-resolver-evidence]]): "10 of 13 misfilings → zero" after adding the brain resolver. This is the most concrete evidence in the whole series for [[patterns/composition/resolver-routing-table]], and it grounds to a *real* artifact: gbrain's `RESOLVER.md` ([[sources/garrytan--gbrain#skills-resolver]]) plus `_brain-filing-rules.md` ([[sources/garrytan--gbrain#skills-brain-filing-rules]]), whose own text reads "Entity propagation is mandatory" — matching the essay's "Does the entity propagation complete?" invariant. (See Contradictions for the 80-vs-128-line discrepancy.)
- **The ~200-line fat-skill shape, stated explicitly** ([[sources/garrytan--naked-models#constraints-not-chaos]]) — "a 200-line document that says: here's the task… here are the tools you have, here are the ones you don't, here's what to do if you're uncertain." A crisp definition to cite for [[patterns/structural/thin-harness-fat-skills]].
- **The "jagged frontier → routing" reframe** ([[sources/garrytan--naked-models#jagged-frontier]]) — a quotable argument for [[patterns/composition/resolver-routing-table]] as the answer to irregular model capability.
- **The open-harness / "user controls verification" argument** ([[sources/garrytan--naked-models#open-harness]]) — Garry's strongest stated reason the artifacts are open source, linked to Pete Koomen's "AI Horseless Carriages." Useful context for why gstack/gbrain ship as editable markdown rather than a closed API.
- **The honesty caveats** ([[sources/garrytan--naked-models#claude-code-leak]], [[sources/garrytan--naked-models#bathroom-decompose]]) — unusually for a manifesto, Tan concedes "Harnesses fail. Skills encode wrong procedures. Verification layers are only as good as the invariants they check." A counter-weight to the series' triumphalism, and an honest framing for our own pattern pages' counter-example sections.
- A **talked-about / named-person-quoted** signal in its own right (a YC CEO publicly rebutting a famous systems engineer — see Popularity signals).

## Contradictions & tensions (for LINT)

1. **Brain resolver: "80 lines" (essay) vs. 128 lines (snapshot).** `#brain-resolver-evidence` says the OpenClaw brain resolver is "80 lines of markdown, in a numbered decision tree." The real artifact, gbrain `skills/RESOLVER.md` at commit `1580c6d` (2026-05-20), is **128 lines** and is table-structured (trigger → skill rows grouped by section) rather than a strictly *numbered* tree. Reconciliations: (a) the essay predates the snapshot and the file grew; (b) Garry is counting only the decision-tree *body* (excluding the always-on header and the chaining preamble); or (c) "OpenClaw's brain resolver" refers to a private/forked variant, not the public gbrain `RESOLVER.md` (note `garrytan/openclaw` is a separate repo — see #2). Low-stakes, but the wiki should not cite "80 lines" as fact; cite the file. The *qualitative* claim (an explicit routing doc collapsed misfilings) is well-grounded: `_brain-filing-rules.md` exists and literally encodes "Entity propagation is mandatory" + a "Common Misfiling Patterns — DO NOT DO THESE" table.
2. **OpenClaw authorship (carried over from #8).** This essay says "my OpenClaw's brain resolver" ([[sources/garrytan--naked-models#brain-resolver-evidence]]) and the sign-off offers to help you "build your own personal OpenClaw/Hermes Agent" ([[sources/garrytan--naked-models#sign-off]]) — i.e., Garry speaks of OpenClaw possessively. Essay #8 states plainly that **Peter Steinberger built OpenClaw** ([[sources/garrytan--foxconn-factories#openclaw]]). Same reconciliation already on file: OpenClaw is Steinberger's harness; `garrytan/openclaw` is Garry's fork/deployment that *runs* gbrain. Flag for consistency with [[creators/garry-tan]] and [[sources/garrytan--gbrain]]; do not silently rewrite.
3. **Pro-test stance here vs. the "Foxconn factory" self-audit in #8.** This essay's whole thesis is "test the system" — unit + integration + resolver evals + LLM-judge + e2e ([[sources/garrytan--naked-models#jepsen-wrong-layer]]). Essay #8's self-audit reports gstack carrying **~276K lines of test code** against **~262K lines of app code** ([[sources/garrytan--foxconn-factories#factory-audit]]) — a >1:1 test-to-app ratio that, by #8's *own* "stop building Foxconn factories" rhetoric, looks like exactly the kind of heavy scaffolding #8 warns against. The tension is real but likely reconcilable: #8 attacks code written to *police a capable model's intelligence*, whereas the tests both essays endorse verify *deterministic* behavior and *routing*, which is the sanctioned use. Worth an analysis once ≥2 essays are ingested; tracked as an open question, not a correction.
4. **"Open harnesses" / user-controls-verification vs. gbrain's guard-rails.** `#open-harness` argues the *user* must own the verification layer ("legalism and safetyism prevent… deep customization"). gbrain itself ships mandatory agent-facing guard-rails — the `AGENTS.md` cost-confrontation gate ([[sources/garrytan--gbrain#AGENTS.md]]) and `_brain-filing-rules.md` marked "MANDATORY for all skills that write to the brain." Not a contradiction (these are *operator-configurable* invariants the operator can edit, which is exactly the openness Garry champions), but a nuance to preserve: "open" here means *editable*, not *unconstrained*.
