In addition to the
upload control parameters
that control what happens during the upload itself, you can also include options in your upload call or upload preset that trigger additional processing after Cloudinary uploads and stores the asset. Even though you specify these options up front, they run asynchronously in the background after Cloudinary stores the asset, and you can use
webhook notifications
to monitor when processing completes.
This page covers the post-upload processing parameters: moderation, analysis, on-success event handling, and running otherwise synchronous operations asynchronously.

Requesting asynchronous uploads
By default, when you call the upload method, Cloudinary processes the upload and returns a response synchronously. However, note that many of the post-upload processing options on this page (such as moderation, analysis, and transcription) always run asynchronously regardless of this setting, and return a
pending
status in the upload response.
For uploads that would otherwise be handled synchronously, you can request asynchronous processing by setting the
async
parameter to
true
. This is recommended for large assets or uploads that include parameters that take a long time to process, where waiting for the synchronous response would result in a poor experience for your users. When
async
is
true
, Cloudinary returns a short response immediately with a
pending
status and a batch ID, and sends the full upload response to your notification URL once processing is complete.
Important
Whenever setting
async
to
true
, make sure to always pass a
notification_url
parameter for the
webhook notification
.
Some optional parameters always process asynchronously regardless of the
async
setting (for example, moderation, transcription, and
raw_convert
). Even without
async: true
, always include a
notification_url
when using these parameters so you know when the additional processing is finished.

Eager asynchronous transformations
Eager transformations generate derived assets (such as different formats, sizes, or optimizations) during upload, making them available immediately upon upload completion. However, when generating multiple eager transformations or processing large assets (particularly videos), processing them synchronously can delay the upload response and degrade user experience.
To improve upload performance and user experience, you can generate eager transformations asynchronously by setting the
eager_async
parameter to
true
. When
eager_async
is enabled, Cloudinary returns the upload response immediately with your main asset, and warms up the cache by generating the transformations in the background, then notifies you when they're ready to serve. This is a best practice for any scenario where you're generating multiple derived assets, and is particularly important for video uploads and agent-based workflows.
Important
Whenever setting
eager_async
to
true
, always provide an
eager_notification_url
so your backend is notified when the eager transformations are ready.
How it works
Set
eager_async
to
true
in your upload parameters
Provide an
eager_notification_url
to receive a webhook notification when transformations are ready
The main asset is uploaded and available immediately in your upload response
The eager transformations (derived assets) are generated asynchronously in the background
When the transformations are ready, Cloudinary sends a webhook notification to your URL with details about each generated asset
