Every asset in Cloudinary has two unique identifiers: a
public ID
and an
asset ID
. They aren't interchangeable. The public ID is the name you use in delivery URLs and in most API calls, while the asset ID is an immutable identifier that stays the same even if the public ID changes.
If you're looking for an asset ID in the Media Library and can't find it, that's expected: the Media Library doesn't display it as a field. This page explains how the two identifiers differ, how to retrieve the asset ID, and when to use each one.
Note
Assets in dynamic folder mode also have a
display name
, which is the name shown in the Media Library. It's a label rather than an identifier: it doesn't have to be unique, it isn't part of the delivery URL, and changing it doesn't affect either the public ID or the asset ID.

You, when you upload the asset. If you don't specify one, Cloudinary assigns a random public ID.

Can it change?
Yes. Renaming an asset changes its public ID, and in the legacy
fixed folder mode
so does moving it between folders. For the full list of reasons, see
Why has an asset's public ID changed?
No. It's immutable for the lifetime of the asset.
Uniqueness
Unique within the product environment for a given asset type and delivery type. The same public ID can exist for both an image and a video.
Unique within the product environment, regardless of asset type, delivery type, or public ID.

Yes. It appears at the end of the delivery URL, before the file extension.
No. You can't deliver or transform an asset by its asset ID.

Yes. The asset ID alone identifies the asset.

The Media Library doesn't show the asset ID as a field in the Summary tab or as a column in List view, but it does appear in the URL of the asset's drill-down page. Double-click an asset to open its drill-down page, then take the value between

Note
You can also paste an asset ID into the

When to use each identifier
Use the
public ID
for:
Building delivery and transformation URLs, either directly or through an SDK.
The majority of Upload API and Admin API calls, together with the asset type and delivery type.
Use the
asset ID
for:
Referencing an asset from your own database or an external system, where you need an identifier that survives renaming an asset, moving it between folders, or changing its display name.
Admin API methods that accept asset IDs, including
get resources by asset IDs

get details of a single resource by asset ID
,
update details of an existing resource by asset ID

, and
delete related assets by asset ID
.
Bulk updating
structured metadata
from a CSV file, where the
assetId
column is an alternative to the
publicId
,
assetType
, and
deliveryType
columns.
Using a stored image as a
reference image for image generation
, by passing its
asset_id
