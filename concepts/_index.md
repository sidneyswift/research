- [[concepts/evidence-calibrated-research]] — preserve confidence, source coverage, and contradictions when synthesizing research.


Ideas and techniques worth their own page — especially from essays, papers, and threads where the durable output is a *concept*, not a runnable artifact. Each page uses [../\_schemas/concept.md](../_schemas/concept.md).

A concept becomes a **pattern** (in `patterns/`) once we've observed it as a concrete technique across **≥2 artifacts** in this wiki. Until then it lives here (or as a `proposed` pattern on an artifact page).

## Cataloged concepts

- [[concepts/review-cost-aware-workflows]] — Choose workflow depth and review surfaces around human decision cost; review facts and choices before expensive implementation.
- [[concepts/artifact-centered-agent-context]] — Give facts, decisions, design, and execution progress explicit artifact owners; pass bounded context into fresh sessions.
- [[concepts/agent-control-plane]] — Separate durable tasks, access, artifacts, and review from provider-specific sessions and execution hosts.

- [[concepts/compound-engineering]] — **the wiki's first concept page.** Every's (Kieran Klaassen's) AI-native development methodology: structure work so each unit makes the next easier; 80/20 planning-vs-execution, the 50/50 features-vs-systems budget, "taste belongs in systems, not review." The named, productized, *independently-arrived-at* twin of [[patterns/quality-bar/complexity-ratchet]]; embodied by [[artifacts/plugins/compound-engineering]]. Sources: [[sources/every--compound-engineering]], [[sources/every--compound-engineering-gets-an-upgrade]].
- [[concepts/completion-contract]] — an agent objective specified as a persistent, evidence-verified *contract* (outcome + verification surface + constraints + boundaries + iteration policy + blocked stop condition), so the agent runs "work → check → continue or complete" and "done" is decided by **evidence, not confidence**. OpenAI's term, productized as Codex Goals; embodied by [[artifacts/projects/codex-goals]]. Source: [[sources/openai--using-goals-in-codex]].
- [[concepts/convergent-agent-plugin-spec]] — Anthropic `.claude-plugin/` and OpenAI `.codex-plugin/` share the same auto-discovered `skills/`/`commands/`/`agents/`, an identical `hooks.json` (`PostToolUse`/`matcher`) grammar, `.mcp.json`, and a `marketplace.json` registry — diverging mainly on connectors (`.app.json` hosted apps vs self-config MCP) and storefront. **Updated 2026-06-04, `status: active`:** the *skills* layer is now a formal open standard (agentskills.io, AAIF/Linux Foundation, 40+ clients) that OpenAI adopts by name; the *plugin* layer remains 2-lab convergence. Sources: [[sources/openai--plugins]], [[sources/anthropic--plugins-reference]], [[sources/agentskills--specification]], [[sources/openai--codex-skills-doc]].
- [[concepts/workspace-skill-distribution]] — how an org gets skills in front of every member without per-machine installs. OpenAI's stack resolves into four **rails** — repo-as-install (`.agents/skills` scope ladder), admin push (ChatGPT "install skills for other workspace members"), marketplace/workspace sharing, machine scope (`/etc/codex/skills`) — while admin *enforcement* config is deliberately **restrictive-only** (constrain, never distribute). `status: emerging`; proposed pattern inside: the restrictive/additive split (needs a 2nd ecosystem). Sources: [[sources/openai--codex-skills-doc]], [[sources/openai--chatgpt-skills-help]], [[sources/openai--plugins]], [[sources/agentskills--specification]].
- [[concepts/skill-invocation-axis]] — every skill splits on one axis: **who can invoke it.** Model-invoked skills keep a `description` (model/user/other-skills can fire them) and cost **context load**; user-invoked skills (`disable-model-invocation: true`) are human-only, cost **cognitive load**, and *cannot be reached by other skills* — so a user-invoked skill may call model-invoked ones but never another user-invoked one, and piled cognitive load is cured by a **router skill**. A deliberate context-budget lever. `status: emerging` (Matt Pocock articulates the axis; the mechanism is multi-source). Source: [[sources/mattpocock--skills]].
- [[concepts/ubiquitous-language-for-agents]] — Eric Evans's **ubiquitous language** ported to the human↔agent gap: maintain a small `CONTEXT.md` *glossary for the agent* (and nothing else — decisions go in ADRs), built/sharpened actively via `domain-modeling`/`grill-with-docs`, so jargon collapses to single terms, naming stays consistent, and the agent spends fewer tokens. Pocock's "single coolest technique." `status: emerging`. Source: [[sources/mattpocock--skills]].
- [[concepts/filesystem-first-agent-framework]] — **convention over configuration, ported to agents.** An agent *is* a directory; each capability is a file in a known slot; identity is derived from the path; the framework *discovers* the tree instead of reading a registry or one big config object ("the files are the interface… no separate registry to keep in sync"). The agent-domain port of the Rails/Next.js idea. `status: emerging` (n=1 *whole-agent* framework — eve; the Agent Skills "directory = skill" convention is a partial second). Source: [[sources/vercel--eve]].
- [[concepts/durable-agent-execution]] — **durability as the substrate, not a feature.** Run a conversation as a durable workflow: nest work as session → turn → step, checkpoint at every step, replay completed steps after a crash/redeploy, and **park** (suspend holding no compute) whenever the agent waits on a human/OAuth/child — then resume exactly where it left off, days later. Forces the rule "interrupted steps re-run → make side effects idempotent or gate them." `status: emerging` (eve makes it the default, on the open-source Workflow SDK; Codex Goals persist *objective* state as an independent, different-grain cousin). Source: [[sources/vercel--eve]].
- [[concepts/agentic-loop]] — a **loop** is a bounded, self-correcting agent prompt: task + an observable verification check + a named stopping condition (the six-step Observe→Choose→Act→Verify→Record→Repeat-or-stop cycle), the opposite of a one-shot prompt that trusts the model's confidence. "Loops are not permission for an agent to run forever." The repeating-cycle layer above [[concepts/completion-contract]]; specializes into [[patterns/behavioral/evidence-gated-completion]]. `status: emerging`; Forward Future. Source: [[sources/forward-future--loop-library]].
- [[concepts/commit-history-as-training-data]] — mine the **commit-by-commit revision history** of many public instances of an artifact into `(before, after, intent)` training triples, capturing how the artifact actually gets edited over time instead of collecting only finished snapshots. `status: emerging` (n=1 — SHL0MS's `skill-diffs`, applied to `SKILL.md` files across 4 platforms). Grounds [[patterns/quality-bar/defect-derived-validation]]. Source: [[sources/SHL0MS--skill-diffs]].
- [[concepts/imitation-vs-correctness-eval]] — when a training corpus's "gold" is just *whatever got merged* (not a verified-correct reference), split the eval into an **imitation** axis (matches the accepted-edit distribution — lexical + LLM-judge) and a **correctness** axis (a rule-based, gold-independent signal like `linter_delta`), because the two can genuinely diverge (a bigger model wins the judge score but loses lexical fidelity and introduces more rule-detectable defects than the gold). `status: emerging`. Source: [[sources/SHL0MS--skill-diffs]].

- [[concepts/dynamic-workflows]] — Claude Code's model-generated JS harnesses for multi-agent orchestration. The model writes a custom harness per task, spawning subagents with isolated context windows to defeat three named failure modes: agentic laziness, self-preferential bias, goal drift. Six composable patterns cataloged. Extends the skill spec into orchestration (workflows distributed via skills). `status: active`. Source: [[sources/anthropic--dynamic-workflows]].
- [[concepts/ai-search-as-parallel-discovery-layer]] — AI chatbots (ChatGPT, Google AI Overviews, AI Mode) form a **parallel discovery layer** independent of Google organic search — different sources, different citation patterns, different content format preferences. Based on 1 billion data points across 14 Ahrefs studies. YouTube mentions have the highest correlation (0.737) with AI brand visibility; 28.3% of most-cited pages have zero Google visibility. `status: emerging`. Source: [[sources/ahrefs--ai-search-optimization-research]].
