# Compound Engineering and Anthropic skills — source review

Date: 2026-10-27. Operation: QUERY/review of the draft engineering-skill-adoption-study.md. This is a same-family independent source review, not the different-family evaluation required by analyses/_eval-rubric.md. No reviewed skill was invoked; no installation, provider request, publication, or behavior test was performed. Source trees were read only. All dispositions below are proposals, not approvals.

## Scope and evidence limits

Canonical on-disk inventory: 39 Compound bodies (38 in compound-engineering plus coding-tutor) and 17 Anthropic bodies. Excludes Compound test fixtures and Anthropic template. Confirmed clean source checkouts at Compound `3e77a7bd8450fef7270f8b46c0f1865fd7125741` and Anthropic `690f15cac7f7b4c055c5ab109c79ed9259934081`. Compound manifest says 3.9.4; coding-tutor 1.3.0. Anthropic marketplace explicitly registers four document skills, twelve example skills, and claude-api separately. The source inventory at engineering-skill-inventory.json is consistent with these source trees.

**Coverage:** All 39 Compound and 17 Anthropic canonical skill bodies were inspected beyond metadata for workflow modes, inputs/outputs, action semantics, role boundaries, source handling and declared dependencies. Initial truncated batches were followed by bounded body reads and targeted semantic spans. Long repetitive API/code recipes were not exhaustively audited line by line. Action-bearing dependencies were inspected selectively, especially upload, shipping, configuration, worktrees, transcription and evaluation execution. This is complete body-level semantic coverage for this source-based adoption study, not an exhaustive audit of every reference, agent prompt, embedded example or executable dependency. No behavior was tested. Selected adoption candidates still require dependency and host verification.

Notation: `C/<name>` means `sources/every--compound-engineering-plugin/plugins/compound-engineering/skills/<name>/SKILL.md`; `A/<name>` means `sources/anthropic--skills/skills/<name>/SKILL.md`. References/scripts listed in a row are relative to that skill directory. These paths refer to the pinned revisions above, not current upstream behavior. “Reuse” means evaluate existing supported capability, not copy approval. “Configure” means use an observed configuration mechanism; “adapt” means behavior or integration changes are needed.

## Findings that materially change the draft

1. **Review is not automatically read-only.** `C/ce-code-review:60–90` distinguishes interactive (default; applies safe_auto changes), autofix (edits and /tmp artifacts, no commit/push), headless (also edits and writes artifacts), and report-only (no edits/artifacts/PR actions, and cannot switch a shared checkout). Only report-only is suitable as a passive review recommendation. `C/ce-doc-review` and its `references/synthesis-and-presentation.md:245–252` likewise silently apply confidently mechanical fixes; its headless mode is not a no-write mode.
2. **Evidence capture can publish before approval.** `C/ce-demo-reel` delegates to `references/upload-and-approval.md`. That dependency uploads a one-hour public litterbox preview BEFORE asking a destination. Headless mode uploads permanently to configured public R2 or catbox. Local save is an option after preview transmission. For private engineering evidence, adapt to local preview and an explicitly approved publication destination; selecting “Save locally” is not sufficient protection against prior transmission. The source's secret scan is useful but does not establish that all other private content is publishable.
3. **Cleanup is destructive.** `C/ce-clean-gone-branches:46–50` removes associated worktrees with `--force` and branches with `-D`, after whole-list yes/no confirmation. A missing upstream branch is not proof that local work is disposable. Skip unchanged in this workspace. `C/ce-compound-refresh` automatically deletes/consolidates docs when evidence is deemed unambiguous, explicitly says “Delete, don't archive,” and can commit/create a PR in headless mode (`:84–86,392–409,540–561`). A doc-maintenance recommendation must name these mutations and adapt to the owner's retention policy.
4. **A helper can transmit data despite local artifact rules.** `C/ce-riffrec-feedback-analysis` says keep raw recordings local-only by default. Its `scripts/analyze_riffrec_zip.py:300–327` calls OpenAI audio transcription when OPENAI_API_KEY is present; `--no-transcribe` disables it. Local Git exclusion and no external transmission are different properties.
5. **Do not overstate configuration.** `ce-setup/references/config-template.yaml` supports work delegation, pulse settings, and markdown/HTML output. It does not establish supported configuration for arbitrary docs/brainstorms, docs/plans, or docs/solutions destinations. Those paths are embedded in multiple skills and agents. Say “configure supported settings; adapt artifact routing where necessary,” not that all placement is configurable.
6. **The evaluation method is portable; its implementation is not harness-neutral.** Anthropic skill-creator's `scripts/run_eval.py` creates temporary `.claude/commands` entries and invokes `claude -p`; it measures triggering through that surface. `scripts/run_loop.py:194–218` hides test results from the improvement prompt but chooses the winning iteration by test score. That reused selection set is not an untouched final acceptance set. Add held-out acceptance cases before making generalization claims and port trigger tests to the team's actual harness.
7. **State transitions need an explicit team contract.** `ce-work/references/shipping-workflow.md` changes plan status active→completed before commit/PR creation, not after merge/deploy. `lfg` can emit DONE with unresolved CI after three fix cycles once residuals are written to PR. The useful interpretation is workflow completion with durable residuals, not approved scope, merged change, successful deployment, or realized value.
8. **Some candidate workflows actively contact people/systems.** `ce-resolve-pr-feedback` commits/pushes, replies, and resolves threads; `ce-report-bug` creates an issue in EveryInc's repo; `lfg` can file tracker issues and modify PR bodies autonomously. These cannot be bundled under a generic “review/documentation” label.
9. **Teams is an adaptation, not an existing integration demonstrated here.** `ce-slack-research` delegates to Slack MCP and explicitly stops if unavailable, forbidding alternative methods. Anthropic internal-comms references Slack and Google Drive retrieval; neither body proves Teams ingestion or publication. Reuse writing/research contracts while using verified Teams/GitHub connectors and preserving source links, dates, disagreement, and draft status.

10. **Review coverage can be deliberately filtered.** `C/ce-code-review` Stage 5b caps deep validation at 15 findings and drops over-budget findings; validation failures can drop candidates too. Headless/autofix suppress advisory P2/P3 testing/maintainability findings under defined conditions. Preserve coverage, dropped/suppressed counts and degraded-agent status; zero returned findings is not exhaustive assurance.
11. **Routing and dependency details matter.** `C/ce-agent-native-audit` points parity at architecture option 7, while `C/ce-agent-native-architecture` lists parity at 8 and context at 7. `C/ce-plan` treats Markdown and HTML differently for automatic document review. `C/ce-work-beta` declares a delegation reference with sandbox/consent configuration; delegation being disabled by default does not make its activated policy safe by inference.
12. **Maintenance reflects observed code, not necessarily intended policy.** `C/ce-compound-refresh:75` directs docs to match code rather than question whether code is a regression. That is suitable for implementation reference but needs adaptation for normative requirements and accepted architectural decisions. Its deletion safeguards are substantive: current problem domain and inbound dependency checks (:345–380), not merely missing-file detection. The recommendation remains to adapt retention, but describe these checks fairly.
13. **Source-based evaluation has narrower meaning than production acceptance.** `A/mcp-builder:161–178` specifies ten stable, verifiable read-only questions; these do not establish write authorization or mutation correctness. `A/skill-creator` explicitly weakens its web-only variant by dropping baseline and quantitative comparisons. `A/pptx:195–203` insists on a fix-and-verify cycle; adapt it to honest observed issues rather than manufacturing a defect when a rendered review passes.

## License boundaries observed, not a legal determination

- Compound root LICENSE is MIT, copyright 2025 Every; the main plugin manifest says MIT. Carry license/copyright notices for any permitted copied portion and check bundled third-party material. `ce-dhh-rails-style/SKILL.md:181–185` explicitly says Fizzy code examples are O'Saasy and the guide is LLM-generated/not endorsed. Root MIT is not evidence all examples/assets share the same grant.
- Anthropic README explicitly calls docx/pdf/pptx/xlsx source-available, not open source. All four LICENSE.txt files are byte-identical (SHA-256 prefix `79f6d8f5b427252f`); the terms mention governing service agreement and additional restrictions on extraction, retaining copies, reproduction, derivatives and distribution. Do not label these “copy with attribution” candidates. Supported service use, public source access and redistribution rights are separate questions.
- Apache 2.0 LICENSE.txt headers were observed in algorithmic-art, brand-guidelines, canvas-design, claude-api, frontend-design, internal-comms, mcp-builder, skill-creator, slack-gif-creator, theme-factory, web-artifacts-builder and webapp-testing. doc-coauthoring has no sibling LICENSE.txt in this checkout. Its absence must not be silently converted into a permissive grant based on the README's “many skills” sentence. Resolve applicable terms before a redistributed copy. Fonts/templates/assets and third-party dependencies need their own notices check.
- Repository README warns that demonstrated skill implementations can differ from shipped Claude behavior. A local source review is not a test of an installed provider capability.
