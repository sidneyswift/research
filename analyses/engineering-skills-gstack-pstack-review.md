## Shared runtime, permissions and assurance findings

1. The preamble is not merely style boilerplate. It performs update checks, writes session/analytics/config state, offers routing rules that commit CLAUDE.md, can migrate vendored source with git rm after a prompt, supports silent WIP commits/push when configured, and invokes artifact sync on skill boundaries. It contains a blanket `SPAWNED_SESSION=true` rule: auto-choose recommended options and do not AskUserQuestion. The same section later says spawned fallback never BLOCKED. This is materially different from interactive STOP gates, even though headless failures block. An adapter must carry human approvals through delegation explicitly; do not describe all Gstack gates as invariant across hosts.
2. Question tuning includes user-origin checks and one-way-door exclusions, but plan-tune's claim v1 never adapts behavior cannot be read as zero autonomous decisions: per-question never-ask preferences are active immediately and preamble performs AUTO_DECIDE. Profile-based default adaptation and explicit preference enforcement are different mechanisms; preserve that distinction.
3.
