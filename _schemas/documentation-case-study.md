# Documentation case-study supplement

Use within INGEST with [concept.md](concept.md), or [project.md](project.md) when studying a runnable documentation system. Extend an overlapping page before creating another. This codifies the repeated first/second-pass product, architecture, operational, executable-reference and discovery comparisons in [[projects/writing-amazing-developer-docs/README]]. Grounded in [[patterns/composition/resolver-routing-table]], [[patterns/quality-bar/revision-bound-review]] and [[concepts/developer-documentation-design]].

## Input and output

Input: named documentation source/system, audience/task, version/date and bounded question. Output: immutable evidence with reviewed scope; registered source anchors; owning findings with tensions/portable ideas; routes/backlinks/log and explicit checks. Capture volume is not a completeness score.

## Study matrix

| Dimension | Record |
| --- | --- |
| Reader/task | Audience, domain familiarity, intent, starting state and expected result |
| Entry/discovery | Homepage, search, exact error, symbol, deep link, preloaded file, browser or tool retrieval |
| Applicability | Product, API, SDK/runtime, environment, role, locale and supported version |
| Page purpose | Learning, task, reference, explanation, diagnosis, decision, live record or retrospective |
| Example context | Complete project versus excerpt, imports/setup, hidden fixtures, substitutions and copy behavior |
| Verification | Compiled/run/skipped/asserted; fixture/mocked/live; business-result oracle and recovery |
| Meaning in transit | Source/render/export/index transformations; warnings, code, table and figure semantics retained or lost |
| Lifecycle | Proposal/accepted/implemented/deployed; build/publish/serve/index/retrieve/use; archive/supersession/redirect |
| Ownership/authority | Accountable contact/editor versus action permission; dissemination/adoption when consequential |
| Failure/recovery | Observable symptom, discriminating evidence, uncertainty, stop/escalate, mixed state and reversal limits |
| Evidence strength | Author guidance, reported experience, observed association, intervention, benchmark, independent replication |
| Reproducibility | Claimed artifacts versus preserved files; code/data pin, excluded attempts, missing replay inputs; regeneration versus historical restoration |
| Agent interface role | Inventory, raw evidence, generated answer, procedural guidance, business execution or administration; declared background effects, requested/served version, caller identity and fallback |
| Controlled comparison | Exposure/selection versus forced context; same prompt/retrieval/tasks/models when isolating content changes; grounded rubric identity, paired failures and not-measured checks |
| Study methods | Sample, selection/assignment, task, denominator, outcomes, assistance, exclusions, uncertainty and limitations |

## Definition of done

- [ ] Dedup by subject/mechanism/role; owning page follows its primary schema.
- [ ] Reviewed pages/sections identified separately from captured scope; extraction/visual limits explicit.
- [ ] Meaning-bearing assets captured or their absence recorded; supplementary captures never overwrite earlier evidence.
- [ ] Every load-bearing claim has a registered supporting source anchor.
- [ ] Comparisons preserve source versions, denominators, publisher-policy differences and contrary findings.
- [ ] Runnable/current/recommended/task-suitable properties and compile/run/skip/outcome checks not conflated.
- [ ] Full-paper redistribution limits honored; original notes retain version/hash restoration where full text is not preserved.
- [ ] Portable ideas, counterexamples, unanswered questions, indexes/backlinks and log updated.
- [ ] Hash/byte receipts and newly added links/anchors checked; inherited issues reported separately.
- [ ] Reproducibility claims checked against actual preserved inputs, not only publisher instructions; missing artifacts explicit.
- [ ] Proposed experiments/templates distinguished from executed outcomes; no population effect inferred from a synthetic probe.
- [ ] An `analyses/` synthesis remains draft until its [cross-family review gate](../analyses/_eval-rubric.md) passes.

This template organizes evidence, not a new vendor ranking or a mandatory documentation taxonomy. Human/agent task evaluation remains necessary before claiming effectiveness in the target platform.
