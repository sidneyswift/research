# What the accessible-chat review teaches us

These are **model-inferred candidates for private review**. They are not universal rules, verified incident statistics, or evidence that a proposed remedy improves a model. The authoritative annotations and their limits are in [reviews.jsonl](reviews.jsonl); [review-catalog.md](review-catalog.md) renders them for reading. Message-linked records are in [interventions.jsonl](interventions.jsonl), with broader candidates in [lessons.jsonl](lessons.jsonl). No adjacent messages have automatically been converted into preference pairs.

These are candidate assertions, not instructions to add every check to every task. For example, an argument-only test is valid when its explicitly limited purpose is tool routing; it does not establish artifact correctness. A guided usability session can answer operational questions while leaving first-glance understanding untested.

## Holistic failures need trajectories

**The technical dependency becomes the project.** A long build accumulated reviewed primitives while a useful customer journey stayed thin or disabled. The user repeatedly restored the data-first MVP and asked for a real task, a reusable capability, completion through the product, then a second case. The candidate remedy is a separate milestone for that complete journey, with foundations tracked as dependencies. Later explicit authorization for broader product work must remain part of the timeline. [[sources/codex--conversation-corpus-20261102#C0322]] The fixed-reply messaging case is analogous: architecture work delayed the smallest requested acknowledgment; later AI and group support were genuinely added scope. [[sources/codex--conversation-corpus-20261102#C0472]]

**A locally reasonable edit damages the overall objective.** Commercial drafting repeatedly expanded promises, revived settled topics, added technical acceptance machinery and blurred client protection with the adviser's opportunity. Subsequent simplification sometimes removed the decision sequence itself. Preserve the immediate recipient decision, active commitments and milestone order across document and email revisions. Human frustration about a supplier is context to examine, not proof of motive or inefficiency. The earlier SOW work and the redline pilot belong to one provisional task family, not independent samples. [[sources/codex--conversation-corpus-20261102#C0310]] [[sources/codex--commercial-redline-pilot#artifact-state]]

**Synthetic agreement creates false closure.** Repeated reviewer verdicts did not establish user comprehension. In engineering chats, green checks also missed shared blind spots until a different fixture, native interaction or actual producer/consumer boundary was examined. The lesson is to diversify the evidence being tested, rather than count reviewers or rerun unchanged checks indefinitely. Preserve later retractions next to the original verdict. [[sources/codex--conversation-corpus-20261102#C0132]] [[sources/codex--conversation-corpus-20261102#C0440]] [[sources/codex--conversation-corpus-20261102#C0442]]

**Diagnosis outruns evidence.** Missing data, provider failure and stale UI sometimes became confident causal stories before the exact live record, current component or real fixture was inspected. Several chats include good explicit retractions. A useful record therefore preserves hypothesis, observation, revised explanation and unresolved cause as separate states; it does not retain only the final confident summary. [[sources/codex--conversation-corpus-20261102#C0034]] [[sources/codex--conversation-corpus-20261102#C0040]] [[sources/codex--conversation-corpus-20261102#C0438]] [[sources/codex--conversation-corpus-20261102#C0440]]

**The agent hands back work it can still perform.** Repeated requests to finish sometimes uncovered real remaining software defects after an earlier blocker summary. Elsewhere, an access test or source read was delegated to the user before documented alternatives were exhausted. The candidate rule is to complete authorized independent work and identify the exact external dependency. It does not authorize bypassing a permission denial or claiming unavailable physical-device acceptance. [[sources/codex--conversation-corpus-20261102#C0121]] [[sources/codex--conversation-corpus-20261102#C0459]] [[sources/codex--conversation-corpus-20261102#C0492]]

**Simplification becomes loss of meaning.** Shorter emails, cleaner diagrams and smaller worksheets sometimes discarded the relationship, synchronization mechanism or decision that made the output useful. Other iterations were ordinary evolving taste. Preserve semantic requirements while reducing presentation load; keep preferences scoped to the user and artifact type. [[sources/codex--conversation-corpus-20261102#C0143]] [[sources/codex--conversation-corpus-20261102#C0484]] [[sources/codex--conversation-corpus-20261102#C0464]]

**The agent explains a lesson without changing the workflow.** In the long design program, generation races, omitted newly tracked sources and self-referential source/evidence commits recur after explicit explanations of their fixes. This is a stronger failure signal than one mistaken command: the supposed learning did not transfer to the next wave. Prefer one executable dependency-ordered operation and a clean-state acceptance pass over another prose reminder. Keep the repair's later recurrence in the episode rather than treating each announcement as closure. [[sources/codex--conversation-corpus-20261102#C0136]] Related cleanup and release records belong to the same provisional program family, not additional independent samples. [Task families](task-families.jsonl).

**The evaluation system becomes its own source of false confidence.** Review-card polish did not supply the query and answer a human needed. New ungraded retries removed old failed badges. Safety abstentions alternated between pass, capability failure and unverified status. Incomparable batches produced a misleading improvement chart. The candidate remedy is to version the rubric and retain independent fields for safe behavior, task completion, grading maturity, attempt validity and source access. The source's later template-invalidity story conflicts with its earlier concrete runtime bindings; that contradiction remains open rather than being accepted because it came last. [[sources/codex--conversation-corpus-20261102#C0221]]

**A completeness validator shares the omission it should detect.** Large inventories passed tests built around the same candidate matcher, while live content and route categories remained invisible. Content hashes also proved byte identity without proving an observation occurred. Use an independent discovery boundary and separately authenticated observation evidence. Temporal provenance tests must exercise the production collector through merge and later-child states, not a helper no longer called by production. [[sources/codex--conversation-corpus-20261102#C0136]]

## Was the intent specified or discovered together?

The review did **not** consistently label opening intent or task mode across all 498 reviewed chats. No defensible percentage of specification versus exploration can be inferred from intervention totals, chat length, correction keywords or the selected failure synthesis. These are not representative prevalence statistics. Visible openings may also omit earlier decisions in other chats or artifacts. The following is a qualitative finding, not a new corpus-wide classification.

A clear outcome can coexist with undecided means, priorities or taste. In the commercial-redline pilot, broad review was requested; the no-upfront-approval constraint became explicit later, a numerical target originated with the user, and a later reversal reconsidered a previously disclosed substantive change. Those are clarification or decision evolution, not proof the agent violated the initial request. Stale explanations after the reversal remain a separately observable consistency problem. [[sources/codex--commercial-redline-pilot#operational-intent]] [[sources/codex--commercial-redline-pilot#evaluation-provenance]] [[sources/codex--commercial-redline-pilot#commitment-evolution]] [[sources/codex--commercial-redline-pilot#changes-only]]

The same conversation can contain both exploration and clear execution obligations. The messaging rollout had an immediate fixed-reply milestone that was delayed, while later group/audience policy was clarified and changed. The planner's day-first design emerged through iteration; shared audiences, time recording and recurrence were later requirements rather than automatically defects in the original scope. The engineering-workspace plan evolved through discussion of real departmental workflows. [[sources/codex--conversation-corpus-20261102#C0472]] [[sources/codex--conversation-corpus-20261102#C0132]] [[sources/codex--conversation-corpus-20261102#C0464]]

For a future quantified pass, annotate **task phases**, allowing mixed mode: execution against an explicit requirement, joint exploration, new information/clarification, changed decision, and unresolved ambiguity. Record the earliest evidence that each requirement became available, whether the agent acknowledged it, the active artifact revision, and whether the later action conflicts with it. A hindsight interpretation must not backdate a newly discovered preference into the initial specification. Separately assess whether the agent helped discovery effectively: useful alternatives, concrete tradeoffs, reversible experiments and faithful incorporation of each decision. Exploratory iteration can be productive; ignoring an established decision, representing an assumption as settled, or repeating avoidable rework is a distinct finding.

## Successful controls matter too

- Several chats clearly separate local code, merge, deployment, provider activation and real outcome. Preserve those distinctions as positive examples rather than label every incomplete external step a failure. [[sources/codex--conversation-corpus-20261102#C0120]] [[sources/codex--conversation-corpus-20261102#C0468]] [[sources/codex--conversation-corpus-20261102#C0469]]
- A future-mail rule was created without treating bulk historical-mail handling as automatically approved. Unrelated local work was also preserved in other changes. These are useful scope controls. [[sources/codex--conversation-corpus-20261102#C0480]] [[sources/codex--conversation-corpus-20261102#C0110]]
- Inferred duplicate identity was eventually left unconfirmed instead of silently consolidating accounts. That recovery should remain visible alongside earlier overconfidence. [[sources/codex--conversation-corpus-20261102#C0041]]
- Some scans correctly produced no new code; some user comments supplied new facts or changed the goal. Neither is evidence of agent error by itself. [[sources/codex--conversation-corpus-20261102#C0439]] [[sources/codex--conversation-corpus-20261102#C0423]]

## How this becomes a usable dataset

The current output supports browsing and hypothesis development. An intervention still needs a verified pre-correction context cutoff, exact failed output/action, feedback authorship, repair revision and outcome before becoming a supervised or preference example. Some extracted records have only a feedback locator; some lessons are explicitly chat-level. Empty `context_cutoff` and `desired_target` fields are intentional gaps, not approval to infer them.

Before evaluation or training, adjudicate the candidate, resolve attachment and tool gaps, apply permissions, and group the complete task family. Development probes here were written after studying the cases: they are **not held-out evaluations**, have not been executed, and demonstrate no measured improvement. Keep the source evidence, annotations and provider-specific export separate. [[projects/conversation-learning/data-contract]] [[projects/conversation-learning/review-protocol]]
